1. 문서 목적과 구현 범위
본 문서는  청소년용 마음상태검사 60문항을 단디 플랫폼 또는 별도 심리검사 시스템에 구현하기 위한 개발자용 기능 명세서이다. 프론트엔드 문항 제시부터 응답 저장, 자동채점, 위험경보, 결과문 조립, 보고서 생성, 사례관리 연계까지 일관된 규칙을 제공한다.
1.1 구현 대상
고정 혼합배치된 60문항 제시 및 검사 세션 관리
일반 4점 척도와 안전문항 전용 척도 처리
미래희망 요인의 역채점 처리
9개 일반요인 점수와 1개 안전요인 별도 산출
문항 응답 즉시 안전·환경 경보 평가
요인별 초록·노랑·빨강 분류와 사례코드 산출
청소년용, 부모·보호자용, 교사·상담자용 결과문 생성
맞춤 솔루션 추천, 재검 일정, 사례관리 상태 저장
검사 정의, 채점규칙, 결과 템플릿의 버전관리
권한별 민감정보 노출 통제와 감사로그 기록
1.2 구현 제외 또는 별도 모듈
정신질환 자동진단 또는 의료적 처방 결정
AI가 단독으로 자살위험을 확정하거나 사례를 종결하는 기능
보호자에게 민감 응답을 무조건 자동 전송하는 기능
표준화 이전의 백분위·T점수 확정 제공
기관별 법적 신고 절차의 완전 자동화
[표시작]
핵심 원칙검사 엔진은 “점수 계산기”가 아니라 발견 → 안전확인 → 이해 → 연결 → 실천 → 변화추적을 지원하는 사례관리 보조 시스템으로 구현한다.

2. 핵심 설계 원칙
[표시작]
원칙 | 개발 적용
비진단 원칙 | 모든 결과문에서 진단 확정 표현을 금지하고 “현재 어려움이 높게 나타남”, “전문적 확인 권고”와 같은 선별 언어를 사용한다.
안전 우선 원칙 | 전체 총점이 낮아도 자해·자살, 학대·폭력, 온라인 착취 등 특정 응답이 양성이면 안전경보가 최종판정보다 우선한다.
고정 혼합배치 | 요인별 묶음 반응을 줄이기 위해 문항을 혼합하되, 표준화와 재현성을 위해 개인별 무작위 섞기는 기본적으로 사용하지 않는다.
문항 ID와 표시순서 분리 | 문항의 의미를 나타내는 영구 item_id와 검사 화면 순서 display_order를 분리하여 향후 순서 변경과 버전관리를 지원한다.
버전 고정 | 검사를 시작한 세션은 시작 당시의 assessment_version, item_version, scoring_version, template_version을 끝까지 사용한다.
민감정보 최소노출 | 청소년·보호자·교사·상담자별로 결과 필드를 구분하고, 자해·학대·성착취 세부응답은 최소권한 원칙으로 제한한다.
설명가능성 | 모든 점수와 판정은 어떤 문항, 규칙, 템플릿이 적용되었는지 추적 가능해야 한다.
실패 안전성 | 경보 전송 실패, 담당자 미확인, 보고서 생성 실패 시 조용히 무시하지 않고 재시도·상위 알림·감사로그를 남긴다.
[표끝]

4. 60문항 고정 혼합배치 및 문항 마스터
문항은 10개 요인이 연속적으로 드러나지 않도록 고정 혼합배치한다. 안전문항은 후반부에 한꺼번에 몰아넣지 않고 중간중간 분산하되, 문항별 시간기준과 응답척도를 화면에 명확히 표시한다. 개인별 무작위 순서변경은 표준화 전 기본값으로 금지한다.
[표시작]
ID 설계Q001~Q060은 화면 표시순서 ID이다. DEP01, SAF04와 같은 item_id는 문항의 영구 의미 ID이며, 향후 표시순서가 변경되어도 유지한다. 데이터 저장과 채점은 item_id를 기준으로 수행한다.
[표끝]

4.1 혼합배치 검증 규칙
동일 요인 문항은 연속 배치하지 않는다.
긍정형 역채점 문항 FUT04~FUT06은 검사 후반에 분산한다.
안전문항은 Q010, Q018, Q026, Q034, Q042, Q060에 분산한다.
안전문항이 제시될 때마다 화면 상단에 해당 시간기준을 다시 표시한다.
SAF 문항 응답은 다음 문항 이동 전에 로컬 및 서버 경보 규칙을 평가한다.
검사 정의 버전이 같으면 모든 대상자에게 동일한 순서를 사용한다.

[표시작]

[표끝]

6.4 전체 위험지수
자해·자살 안전요인 SAF는 전체 위험총점에 포함하지 않는다. 9개 일반요인이 모두 COMPLETE인 경우 전체 위험지수는 두 방식이 동일하다.
전체 위험지수
[표시작]
overall_raw = DEP + ANX + IMP + TRM + ISO + FAM + LIF + RSK + FUToverall_index = ROUND(overall_raw / 162 * 100, 1)# 또는 9개 factor risk_index의 산술평균

8.3 판정 우선순위
acute_emergency가 true이면 일반 보고서보다 긴급 대응화면과 담당자 연결을 먼저 실행한다.
C3, C2, C1 순으로 안전·환경 코드를 우선한다.
안전코드가 없으면 R2, R1, Y2, Y1, G0 순으로 일반 사례코드를 적용한다.
전체 위험지수는 보고서 설명용으로 제공하되 최종 사례코드를 낮추는 데 사용하지 않는다.
점수 미산출 요인이 있으면 final_score_status를 PARTIAL 또는 INCOMPLETE로 표시한다.
9. 결과문 생성 엔진 규칙
9.1 대상별 결과 채널
[표시작]
audience_code | 대상 | 노출 범위
YOUTH | 청소년 본인 | 쉬운 언어, 상위 3요인, 강점, 실천과제, 안전연락처
GUARDIAN | 부모·보호자 | 요인 요약과 지원행동. 민감 세부응답은 자동 비공개
TEACHER_SUMMARY | 일반 교사·지도자 | 기능적 지원 필요와 기관 내 행동지침 중심
PROFESSIONAL | 전문상담자·임상가 | 문항응답, 경보, 점수, 추가면담 질문, 사례개념화

[표끝]
9.2 템플릿 키
키 명명규칙
[표시작]
result.{audience}.{factor}.{band}.{component}예: result.YOUTH.DEP.RED.meaning    result.GUARDIAN.DEP.RED.actions    result.PROFESSIONAL.DEP.RED.clinical_note
[표끝]
component는 headline, meaning, action, avoid, referral, followup, strength, safety_notice 등을 사용한다. 문안은 코드에 하드코딩하지 않고 interpretation_templates 테이블에서 버전별로 관리한다.
9.3 결과문 조립 순서
안전·환경 경보가 S1/E1 이상이면 안전 안내 블록을 최상단에 배치한다.
요인별 priority_score를 계산하여 상위 3개 요인을 선정한다.
상위 요인은 상세문안을, 나머지는 표 형식 요약문안을 사용한다.
보호요인 또는 강점을 최소 1개 포함한다.
청소년용은 최대 3개의 실천과제, 보호자용은 최대 3개의 지원행동, 전문가용은 최대 5개의 개입권고를 제시한다.
중복되는 솔루션은 dedupe_group으로 하나만 남긴다.
마지막에 재검시점과 비진단 고지문을 붙인다.
9.4 요인 우선순위
동일한 신호등·위험지수일 때의 운영상 우선순위는 다음과 같다. 이는 진단적 중요도의 순위가 아니라 결과문을 결정하기 위한 결정적 tie-breaker이다.
동점 우선순위
[표시작]
SAFETY > DEP > TRM > FAM > RSK > IMP > ISO > LIF > ANX > FUT
[표끝]
9.5 우선순위 점수
상위요인 선정
[표시작]
severity_weight = {'GREEN':0, 'YELLOW':100, 'RED':200}priority_score = (    severity_weight[band]    + risk_index    + alert_bonus    + tie_break_weight)# alert_bonus: 해당 요인에 HIGH/CRITICAL 경보가 있으면 +1000
[표끝]

10.2 추천 규칙
S2/S3 또는 E2/E3가 있으면 안전 솔루션을 첫 번째로 고정한다.
상위 3개 요인의 band에 맞는 솔루션을 선택한다.
dedupe_group이 같은 솔루션은 가장 우선순위가 높은 하나만 유지한다.
청소년용 실천과제는 한 번에 3개 이하, 1개 과제는 5~15분 안에 시작 가능한 행동으로 제시한다.
부모용은 비난·강압 금지와 구체적 지원행동을 포함한다.
전문가용은 추가평가, 개입, 연계, 재검을 구분하여 제공한다.

12. 데이터베이스 테이블 설계
권장 DB는 PostgreSQL이다. 검사 정의와 실행데이터를 분리하고, 신원정보는 가능하면 별도 Identity/CRM 영역에 저장한다. assessment_session에는 내부 subject_id만 저장하고 이름·전화번호 등의 직접식별자는 최소화한다.

테이블 | 목적 | 핵심 필드
assessments | 검사 제품 기본정보 | assessment_id, code, name, status
assessment_versions | 검사 버전 스냅샷 | assessment_version_id, version, published_at
factors | 요인 정의 | factor_id, code, name, display_order
items | 영구 문항 ID | item_id, factor_id, sensitivity
item_versions | 문항 문구·순서·척도 버전 | item_version_id, text, display_order, reverse_scored
response_scales | 응답척도 | scale_code, options_json
scoring_rules | 채점·절단점 규칙 | scoring_version, rule_type, rule_json
alert_rules | 안전·환경 경보 | rule_code, expression_json, severity
interpretation_templates | 결과문 템플릿 | template_key, audience, text, version
solution_catalog | 솔루션 콘텐츠 | solution_code, factor_code, steps_json
assessment_sessions | 검사 세션 | session_id, subject_id, version refs, status
responses | 문항 응답 | session_id, item_id, raw_value, scored_value
factor_scores | 요인별 산출값 | session_id, factor_code, raw, risk_index, band
assessment_results | 종합판정 | overall_index, safety levels, case codes
alert_events | 발생 경보 | rule_code, severity, ack_status

12.1 핵심 관계
assessments 1:N assessment_versions
assessment_versions N:M item_versions(버전 스냅샷 연결)
assessment_sessions N:1 assessment_versions / scoring_versions / template_versions
assessment_sessions 1:N responses, factor_scores, alert_events, reports, case_actions
alert_events 0:1 또는 1:N safety_assessments
consent_records는 subject/session/report disclosure 범위를 제어
audit_logs는 민감 데이터 조회와 변경을 모두 기록

status = 'COMPLETE'        elif len(values) == 5:            raw = round(sum(values) * 6 / 5, 1); status = 'PARTIAL'        else:            raw = None; status = 'UNSCORABLE'        risk = None if raw is None else round(raw / 18 * 100, 1)        band = determine_band(raw) if raw is not None else None        factor_scores.append(build_factor_result(factor, raw, risk, band, status))    # 3. 안전 및 환경 경보    suicide_level = evaluate_safety_level(responses, quality)    environment_level = evaluate_environment_level(responses, session.context)    acute_emergency = evaluate_acute_emergency(latest_safety_assessment(session_id))    create_or_update_alert_events(session_id, responses, suicide_level, environment_level)    # 4. 일반/최종 사례코드    general_code = classify_general_profile(factor_scores)    final_code = classify_final_case(general_code, suicide_level, environment_level)    # 5. 전체지수    overall = calculate_overall(factor_scores)    # 6. 강점·솔루션·재검    strengths = extract_strengths(responses, quality, session.context)    ranked_factors = rank_factors(factor_scores, open_alerts(session_id))    solutions = recommend_solutions(ranked_factors, suicide_level, environment_level)    recheck = recommend_recheck(final_code, ranked_factors)    # 7. 원자적 저장    save_factor_scores(...)    save_assessment_result(...)    mark_session_completed(...)    return structured_result(...)

def generate_report(session_id, audience, actor):    result = load_result(session_id)    assert can_generate_report(actor, audience, result)    sections = []    if max_level(result.suicide_level, result.environment_level) >= 1:        sections.append(render_safety_notice(audience, result))    sections.append(render_overall_summary(audience, result))    top_factors = select_top_factors(result.factors, limit=3)    for factor in top_factors:        sections.append(render_factor_detail(audience, factor))    sections.append(render_strength(audience, result.strengths))    sections.append(render_solutions(audience, result.solutions))    sections.append(render_recheck(audience, result.recheck))    sections.append(render_disclaimer(audience))    sections = apply_disclosure_policy(sections, audience, actor, result.consents)    report = persist_versioned_report(sections, result.template_version)    audit('REPORT_GENERATED', actor, report)    return report

17.2 통합테스트
Q001~Q060이 정의된 고정순서로 노출되는지 확인
안전문항 응답 직후 결과 완료 전에도 경보가 발생하는지 확인
오프라인 응답 동기화 시 경보가 누락되지 않는지 확인
세션 시작 후 검사 정의가 새 버전으로 배포되어도 기존 세션이 원래 버전을 유지하는지 확인
보호자 계정으로 SAF 원응답 API를 직접 호출할 때 403이 반환되는지 확인
보고서 문안과 점수·신호등이 정확히 일치하는지 확인
경보 알림 실패 시 재시도와 상위 담당자 에스컬레이션이 작동하는지 확인
검사 완료 트랜잭션 중 오류가 나도 원응답이 손실되지 않는지 확인
17.3 검수 금지사항
안전문항 응답거부를 0점으로 처리하지 않는다.
전체 총점이 낮다는 이유로 S/E 경보를 제거하지 않는다.
보호자용 보고서에 문항별 자살·학대 응답을 자동 삽입하지 않는다.
표준화 전 백분위·T점수를 임의 생성하지 않는다.
문항 문구 변경 후 같은 assessment_version을 재사용하지 않는다.
경보를 담당자가 확인하지 않았는데 자동으로 RESOLVED 처리하지 않는다.

부록 C. 버전관리 원칙
문항 문구, 표시순서, 척도, 역채점 여부가 바뀌면 assessment_version을 올린다.
절단점, 경보조건, 종합판정 수식이 바뀌면 scoring_version을 올린다.
결과문 또는 솔루션 내용만 바뀌면 template_version을 올린다.
기존 세션과 보고서는 당시 버전으로 재현 가능해야 한다.
재채점 기능을 제공할 경우 original_result와 rescored_result를 모두 보존하고 변경사유를 감사로그에 기록한다.
표준화 완료 시 norm_version을 발행하고 백분위·T점수 필드를 활성화한다.
