# 심지(simji) 현재 구현 사이트 — 협의용 정리 문서

작성 2026-07-02. **지금 배포/구현되어 있는 상태 그대로**를 기준으로 정리한 문서입니다.
"협의"에서 무엇이 이미 되어 있고(엔진), 무엇이 아직 껍데기(콘텐츠·목업)인지 구분해 다음 결정을 내리기 위한 자료입니다.

> 한 줄 요약: **검사 응시·채점·결제·검사권·회원가입 "엔진"은 실제로 완결 동작**합니다.
> 반면 **검사 종류·연령방 라인업·코칭·상단 소개 페이지·실결제(PG) 연동은 샘플/목업** 수준입니다.
> 즉 "기계는 돌아가는데, 아직 내용물(검사 콘텐츠)과 바깥 포장(소개 페이지)이 비어 있는" 상태입니다.

- 기술 스택: Laravel (Blade + Tailwind), 카카오 소셜로그인(Socialite)
- 브랜치: `feat/partial-implementation` (내부검토용 Render 프리뷰 배포)
- 실제 시드된 검사: **단 2종**(무료 샘플 1, 유료 샘플 1)

로고(심지) 좌측 + 7개 메뉴 + 우측 로그인/회원가입(또는 내 검사함).
정의 위치: `resources/views/components/header.blade.php`

|---|---|---|---|

## 2. 연령방(마음방) 개념 — 검사를 묶는 단위

복잡한 검사 목록 대신 **"나는 지금 어느 방에 있나?"** 로 먼저 고르게 하는 구조.
정의: `app/Support/Rooms.php` (코드 하드코딩 배열)

| 방 코드 | 이름 | 대상 | 예정 검사(목데이터) |
|---|---|---|---|
| `elem` | 초등학생 | 부모·교사가 대신 응답 | 마음안전선별·정서행동·사회성·주의집중·스마트폰 (보호자 응답형) |
| `middle` | 중고등학생 | 학생 본인 | 청소년 마음상태·학업스트레스·시험불안·진로성향·대인관계 |
| `univ` | 대학생 | 본인 | 우울·불안·스트레스·진로정체감·대인관계·자기조절 |
| `worker` | 직장인·성인 | 본인 | 번아웃·직무스트레스·분노조절·회복탄력성 |
| `silver` | 실버 | 본인·가족 | 실버 마음상태·우울고독감·인지건강·삶의만족도 |

**주의 — 방별 라인업은 "예정 검사 목록(planned_tests)"일 뿐**, 실제 DB에 있는 검사와 무관합니다.
- 방 자체와 라우팅(`/tests/room/{code}`)은 **실제 동작**. `Test.room` 컬럼이 방 코드와 매칭되어 그 방의 실제 검사만 보여줌.
- 하지만 현재 실제 검사가 있는 방은 **`worker`(무료 1), `univ`(유료 1)** 뿐. **elem·middle·silver 방은 들어가면 비어 있음.**

## 3. 검사 사용 흐름 — 단계별 시나리오

라우트: `routes/web.php:31-40` · 로직: `app/Http/Controllers/AssessmentController.php` · 채점: `app/Services/ScoringService.php`

### 사용자가 실제로 겪는 화면 흐름

```
홈 또는 심리검사 탭
   → [연령방 선택]  /tests            (5개 방 카드)
   → [방 입장]      /tests/room/elem   (그 방의 검사 목록)
   → [검사 선택]    /tests/{code}      (검사 상세 — 문항수·소요시간·유·무료)
        │
        ├─ (검사 시작 클릭)
        │
   → [동의]         /assessment/{code}/consent   개인정보·(필요시)보호자 동의
   → [소개]         /assessment/{code}/intro     검사 안내
        │  ← 여기서 로그인/결제 분기 (아래)
   → [응시]         /assessment/{code}/take/{attempt}   문항 1~5점 라디오, 진행바
        │  (제출)
   → [결과]         /result/{attempt}   신호등 리포트 (초록·노랑·빨강 + 영역 그래프 + 해석 + 추천)
```

### 분기 규칙 (start 단계에서 결정)

- **무료 검사**: 로그인 없이도 응시 가능. **게스트도 OK** — 세션에 `guest_token`을 발급해 이력을 붙임(로그인 안 해도 `/my`에서 자기 결과 보임).
- **유료 검사**:
  1. 비로그인 → **로그인 페이지로** 보냄
  2. 로그인했지만 검사권 없음 → **결제 페이지로**(`/checkout`)
  3. 검사권 있음 → 검사권 1개 소비하고 응시 진행
- **보호자 동의 검사**(`requires_guardian_consent=true`): 동의 화면에서 보호자 동의까지 받아야 통과. 세션 플래그로 확인.
  - ⚠️ **현재 이 플래그가 켜진 검사는 DB에 없음** → 코드는 있으나 실제로 트리거되는 검사가 없어 미검증. (초등 아동검사 붙일 때 선결 필요)

### 채점 방식 (실제 동작)
- 문항 응답(1~5점)을 **영역(area)별로 합산**. 회복탄력성 같은 역방향 문항은 `6 - 점수`로 역채점.
- 영역별 임계값으로 **초록/노랑/빨강 신호** 결정. 전체 신호 = 가장 위험한 영역 색.
- 결과에 영역별 점수·신호·해석문·추천이 `test_results` 테이블에 저장됨.

> **이 전체 흐름(동의→응시→채점→신호등 결과)은 실제로 끝까지 동작합니다.** 게스트 응시, 유료 검사권 소비까지 포함.

## 4. 회원가입 · 로그인

정의: `routes/auth.php` · `RegisteredUserController` · `Auth/KakaoController`

- **회원가입 유형 2종**: `개인(personal)` / `기관(institution)`
  - 가입 방식 선택 화면 → 유형별 폼(`/register/personal`, `/register/institution`)
  - 공통: 이름·이메일·전화·비밀번호·약관동의(필수) / 마케팅동의(선택)
  - 기관: **기관명(organization) 추가 필수**
- **카카오 간편 로그인**: 실제 구현됨(Socialite). 이메일 없으면 `kakao_{id}@simji.local`로 자동 생성. 실제 작동하려면 카카오 앱 키 설정 필요.
- 일반 로그인·비밀번호 재설정·이메일 인증: Laravel 표준(Breeze).
- `users` 테이블 확장 컬럼: `phone`, `marketing_agree`, `user_type`(personal|institution), `organization`.

> 상태: **실제 동작**(개인/기관 구분 + 카카오까지).

## 5. 결제 · 검사권

정의: `CheckoutController` · `PaymentController` · `CheckoutService` · `VoucherService`

- **상품(Product)**: 검사 1종에 연결. 가격·검사권 수량(기본1)·유효기간(기본 365일).
- **주문 흐름**: 검사 상세에서 결제 → pending 주문 생성 → 결제창 → 승인 콜백(`/payment/return`) → 성공 시 **검사권 자동 발급** → 유료 검사 응시에서 검사권 소비.
- 멱등 처리·금액 위변조 방어·실패 처리까지 **로직은 완결**.
- ⚠️ **실제 PG(이니시스 등) 연동은 아직 목업(FakeGateway)** — 개발환경에서 "테스트 결제 완료/취소" 버튼으로 시뮬레이션. 운영환경에선 예외 발생하도록 막혀 있음(오결제 방지).

> 상태: **결제 도메인 로직 = 실제 동작 / 실 PG 연동 = 미구현(별도 태스크)**. 개발환경에선 주문→결제→검사권→유료검사 응시가 end-to-end로 돌아감.

## 9. 협의에서 정해야 할 것 (제안)

지금 상태에서 다음 단계로 가려면 결정이 필요한 지점들:

1. **검사 콘텐츠 이관 우선순위** — 어느 연령방부터 실제 검사를 채울지. (기관 주고객 → elem/기관 검사 우선?)
2. **보호자 동의 정책** — 아동검사 오픈 전 서버 강제 선결 필요. 어떤 검사에 켤지.
3. **실 PG 연동** — 결제 붙일 시점·PG사(이니시스 등).
4. **목업 6개 페이지 중 실제로 붙일 기능** — 기관 문의 폼 저장, 전문가 디렉토리 DB화, 코칭 DB화 등 (스키마 초안은 `2026-07-01-mock-screens-schema-draft.md`).
5. **관리자 인증 가드** — 실서비스 전 필수.
6. **기존 단디(카페24) 콘텐츠 이전 범위** — 검사 문항·결과 로직을 어디까지 심지로 옮길지.
