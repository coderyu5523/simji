  - `GEN` 54문항 — 전혀 그렇지 않다 / 가끔 / 자주 / 거의 항상 (0~3)
  - `SAF-T` 4문항 — 전혀 없었다 / 한두 번 / 여러 번 / 자주 있었거나 지금도 (0~3)
  - `SAF-B` 2문항 — 없었다 / 1회 / 2~3회 / 4회 이상 또는 최근 1개월 내 (0~3)
- **기간**: 최근 2주 58문항 / 최근 12개월 2문항(SAF05·SAF06)
- **경보 플래그**: 즉시평가 6개(SAF 전부), 조건경보 5개(TRM06 학대, FAM05 가정폭력, RSK04 술·담배, RSK05 도박, RSK06 온라인 착취)

## 4. 채점 엔진 — 3층 구조

### ① 일반 요인 점수 (`scoreAnswers`, 2132)
```
요인 원점수 = Σ(0~3), SAF 제외 54문항 → 요인당 0~18점
역채점: 3 - value
위험지수 = raw/18 × 100 (소수 1자리)
요인 밴드: raw ≤5 초록 / ≤10 노랑 / 11+ 빨강
전체지수 = 9요인 합 / 162 × 100
전체 밴드: <30 초록 / <60 노랑 / 60+ 빨강
```

### ② 안전등급 S0~S3 (`getSafetyLevel`, 2163)
점수 합산이 **아니라 개별 문항 규칙 기반**.
```
S3: SAF03=3 (자살생각 지속) OR SAF04>=2 (계획·준비) OR SAF06>=1 (12개월 내 자살시도)
S2: SAF01>=2 OR SAF02>=2 OR SAF03=2 OR SAF04=1 OR SAF05>=2
S1: SAF01>=1 OR SAF02=1 OR SAF03=1 OR SAF05=1
S0: 그 외
```

### ③ 환경경보 E0~E3 (`getEnvironmentLevel`, 2177)
```
E3: TRM06=3 (학대) OR FAM05=3 (가정폭력) OR RSK06=3 (온라인 착취)
E2: 위 셋 중 =2 OR RSK04>=2 (술·담배) OR RSK05>=2 (도박)
E1: 위 셋 중 =1 OR RSK05=1
E0: 그 외
```

### ④ 최종 지원 우선코드 (`getFinalCaseCode`, 2201)
```
highest = max(S랭크, E랭크)
highest > 0 이면 → C{highest}   (일반 코드를 덮어씀)
highest = 0 이면 → 일반 코드
```
| 코드 | 명칭 | 산출 |
|---|---|---|
| G0 | 안정·예방군 | 빨강 0, 노랑 0 |
| Y1 | 단일 관심군 | 노랑 1~2 |
| Y2 | 복합 관심군 | 노랑 3+ |
| R1 | 단일 고위험군 | 빨강 1 |
| R2 | 복합 고위험군 | 빨강 2+ |
| C1 | 안전주의군 | max(S,E)=1 |
| C2 | 안전고위험군 | max(S,E)=2 |
| C3 | 긴급위기군 | max(S,E)=3 |

**설계 의도**: 총점이 낮아도 자살·학대 문항 하나가 걸리면 C코드로 격상. 선별도구로서 타당한 방향.

### ⑤ 상위 3순위 (`priorityFactors`, 2221)
`weight(밴드) + riskIndex + tieBreak/100`로 정렬 후 상위 3개.
tieBreak 우선순위: DEP 9 > TRM 8 > FAM 7 > RSK 6 > IMP 5 > ISO 4 > LIF 3 > ANX 2 > FUT 1.

## 6. 발견한 문제

### 🔴 실제 버그 — 안전 모달이 이후 모든 문항에서 반복 팝업
`maybeShowImmediateAlert()` (2293–2311). 중복방지 키가 **문항 단위**인데 발동 조건은 **전역 안전등급**이다.

```js
const key = `${item.itemId}:${state.answers[item.itemId]}`;   // 문항별 키
if (state.shownAlerts.has(key)) return;
const safety = getSafetyLevel();                               // 전역 상태
if (safetyRank >= 2 || environmentRank >= 3) { ...모달... }
```

`selectAnswer()`가 60문항 **모두**에서 이 함수를 호출한다. 10번(SAF01)에 2로 답해 S2가 되면, 이후 11·12·13…번 답할 때마다 새 key가 생성되어 **모달이 계속 다시 뜬다**(최악 50회 연속).

- **원인**: 억제 기준이 "어떤 문항에 답했는가"인데, 실제로 억제해야 할 것은 "어떤 등급의 경보를 이미 보여줬는가".
- **수정 방향**: key를 `` `${safety}:${environment}` `` 또는 도달 최고등급으로 변경 → 등급이 올라갈 때만 재표시.

### 🟡 밴드 절단점 불일치
요인 밴드는 raw 5/10 기준(= 27.8% / 55.6%)인데 전체 밴드는 30/60 기준. 같은 "노랑"이 요인과 전체에서 다른 백분율을 뜻함. **의도 확인 필요.**

### 🟡 E1 하나로 일반 코드가 통째로 가려짐
`getFinalCaseCode`는 `max(S,E) > 0`이면 무조건 C코드 반환. TRM06에 "가끔 그렇다"(=1) 하나만 체크해도 결과 코드가 `C1`이 되어 나머지 9요인이 전부 초록이라는 정보가 코드에서 사라진다. 화면엔 요인별 신호등이 따로 나오니 치명적이진 않으나, **코드만 집계하는 기관 통계에서 C1이 과다 집계**된다.

### 🟢 경미
- `factorScores[].count`는 집계만 하고 미사용 (죽은 코드)
- `priorityFactors`의 `weight` 가산은 밴드가 raw에 단조증가라 사실상 불필요 (결과 동일)
- `state.shownAlerts`는 뒤로 가서 답을 낮춰도 초기화되지 않음
- SAF 요인 원점수(0~18)는 결과화면에 전혀 표시되지 않음 (`FACTOR_META`에 SAF 없음). 의도된 설계로 보이나 명시 필요
